## 3. 片中确认的项目信息

### 3.1 三代火箭与命名

| 时间 | 片中陈述 |
|---|---|
| 2023-02 | 第一代火箭完成，可以监测当前姿态并把数据返回电脑地面端软件 |
| 之后 | 第二代火箭进行初步模块化设计 |
| 第三代 | 命名为 **DustArrow X**；“X 就意味着有着无限的可能” |
| 第三代结构 | 片中称“总共四个部分，可以随意拼接”；粉尘传感器可与气体传感器拼接，组成三个传感器的探测段 |
| 模块化目标 | 探测沙尘暴、酸雨等不同天气时，不更换整个箭体，只更换相应模块 |

片中在 08:08 左右说“四个部分”，而仓库正式 CAD 将箭体细分为十个功能舱段。两者不矛盾：电视用四个功能分组讲述，CAD 用十个舱段实现。该口径差异标记为需要作者确认。

### 3.2 试飞过程

片头把时间放在“2023 年秋末初冬的一天”，地点是“固原市郊外的戈壁滩”。

1. 遥控点火程序测试失败。片中解释为开发板 I/O 口有保护机制，原方案被否定。
2. 改用线控点火，在 7.5 m 距离测试成功。
3. 在戈壁滩安装临时发射架，完成倒计时和发射。
4. 火箭升空后回收。片中陈述：“伞舱部分和推进模块都丢了”，“最重要的传感器部分留了下来”，“回收的完整程度达到了 80%”。
5. 学生表示“比预期要好很多”，片中以“成功”字幕描述这次试飞。

因此，这次试飞可以表述为：**火箭成功离架并完成回收，传感器段被找回；伞舱与推进模块丢失，整箭回收并不完整。** 80% 是学生现场估计，不是独立测量。

### 3.3 地面站与数据链

片中在 08:47 左右说明地面端“读取一个文本文件中的数据，然后完成一些简单的姿态反馈任务”。这与仓库归档代码的行为一致：串口正则解析后写入 `data.txt`，六张图是占位曲线，OpenGL 组件未启用。

学生在 18:04 左右补充了两条数据链设想：

- 设计 SD 卡记录装置；
- 在主控部分增加远程数传装置；
- “理论上是可以实时把数据传回来的”。

这是设计意图，不是片中演示结果。片中未展示遥测日志、SD 卡数据或实时回传画面。

### 3.4 设计理念

- 模块化、可回收；可以连续发射多枚火箭，对沙尘天气做立体分析。
- 现有市售粉尘传感器多为模拟传感器，存在误差；学生希望未来使用更专业、更精密的传感器。
- 项目从个人兴趣出发，逐渐转向为家乡沙尘天气监测提供工具。

## 4. 片中未提供的量化信息

片中**没有**给出以下数据：

- 飞行高度、速度、加速度、姿态角、气压、温度、湿度；
- 粉尘浓度、气体浓度或传感器标定结果；
- 通信距离、RSSI、误码率、链路余量；
- 回收撞击速度、伞舱分离高度或残骸位置；
- 整箭质量、推力、质心或转动惯量。

因此，电视节目不能替代飞行日志、传感器标定或链路预算。它只证明“进行过一次试飞并回收了部分箭体”，不证明“千米级稳定数传”或“精确气象探测”。
